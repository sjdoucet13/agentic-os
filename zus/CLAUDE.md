# zus — Domain Router (ONE domain, FOUR sub-areas)

The **zus-legacy** project — clan tooling + platform for the **ZUS** clan in the game
**Total Battle**. This is **one domain with sub-areas** (the vault's multi-area pattern); the
split must stay visible.

## Sub-areas
| Sub-area | Path | Source | Scope |
|---|---|---|---|
| Web | `web/` | `nextjs-boilerplate` (zuslegacy.com) | Next.js clan-intelligence platform (MongoDB / Vercel) |
| App | `app/` | `zus-legacy-companion` (Android) | Android screen-automation companion |
| Intel | `intel/` | `~/projects/mitmproxy` + `~/projects/TBScores/tb_capture` | Standalone RE/decode tooling (the data contract) |
| Shared | `_shared/` | — | ONLY genuinely-shared concepts (see below) |

## What `_shared/` may hold
ONLY the genuinely cross-cutting **concepts** the platform reasons about: the **ZUS clan domain**
and the **`clanSlug` identity / isolation** rule (the platform's real isolation key), plus the stable
player-identity model. **NO protocol claims** — the binary decode, `clan_id`, field indices, title
map, and export contract live in **`intel/`**, not here.

## What `intel/` holds (knowledge-only; tooling, not a deployed app — no `skills/`)
The standalone reverse-engineering/decode scripts that produce the data the platform ingests: the
LE-MessagePack decode, the `clan_id 1313036` / field-`[12]`-not-tag-`[13]` filtering, the title
id→name map, and the TSV export/ingest contract. **Guardrail:** captures the decode CONTRACT +
constants only — never the ingest script's DB credentials.

## Sub-area relationships (within zus — sanctioned, not contamination)
`intel` defines the data contract; `web` ingests it (the `roster-capture-ingest.ts` bridge upserts the
platform's `Players`). `web` and `app` share **nothing in code** (the app's server-sync is an unbuilt
Phase D). Documenting these intra-zus flows is expected; only TOP-LEVEL cross-domain links are barred.

Data flow: **capture → decode (intel) → export TSV → ingest into web admin → platform**.

## Isolation declaration (vs. other top-level domains)
- `zus` references **only** zus. It does **not** link to `fugro`, `mad`, or `personal`. If something
  seems shared across top-level domains, **stop and ask** — never bridge.
